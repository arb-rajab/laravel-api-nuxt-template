# Security Policy

## Supported versions

Only the latest commit on `main` (or, once you tag releases, the latest
release) receives security fixes. Update this section when that changes.

## Reporting a vulnerability

Please **do not** open a public GitHub issue for security vulnerabilities.

Instead, use GitHub's private vulnerability reporting (Security tab ->
"Report a vulnerability"), or email `<SECURITY CONTACT EMAIL>` directly.

Please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce
- Affected version or commit

## Disclosure process

1. Acknowledgement within 5 business days.
2. Assessment and severity rating.
3. Fix developed on a private branch where feasible.
4. Coordinated disclosure once a fix is released, with credit to the reporter
   unless anonymity is requested.

## Scope

This policy covers this repository's own source, its GitHub Actions workflows
and its published artifacts. It does not cover third-party dependencies
(report those upstream) or the infrastructure providers a deployment uses.
